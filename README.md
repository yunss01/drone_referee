# Drone Referee

드론 영상에서 차량 바퀴의 접지점과 차선을 검출해 점선 침범과 이탈을 판정하는 시스템입니다. 캡처보드 또는 유튜브 라이브 영상을 입력받아 판정 결과를 표시하고 송출합니다.

## 판정 방식

CLAHE 전처리 후 차선 세그멘테이션과 바퀴 접지점 검출을 수행합니다. 차선 마스크에서 PCA 중심선과 반폭을 구하고, 접지점과 중심선 구간 사이의 거리가 반폭보다 작으면 침범으로 판정합니다. 중심선 구간 바깥으로 투영되는 점은 구간 끝점까지의 거리를 사용합니다.

접지점 신뢰도가 낮으면 바퀴 bbox 하단 중앙을 사용합니다. 침범이 설정 시간 이상 지속되면 확정하며, 운영 기본값은 0.1초입니다.

차선이 바퀴에 가려지면 이전에 실제로 관측한 도색 영역을 도로 배경 움직임에 맞춰 현재 화면으로 옮겨 사용합니다. 복원은 바퀴 가림 영역으로 제한하며, 관측한 적 없는 점선 공백을 연장선으로 채우지 않습니다. 같은 바퀴에는 검출 순서와 별도의 추적 ID를 부여합니다.

운영 기준에서 이탈은 접지점이 실제 점선 도색을 넘어 **화면 아래쪽**에 있는 상태입니다. 바퀴 주변 도색 중 접지점과 같은 x열에 실제 픽셀이 있고, 유한한 점선 길이 안에서 접지점이 도색 아래 경계와 오차 여유를 넘었을 때 `LINE OUT`을 표시합니다. 바퀴 bbox가 차선과 겹치는 것만으로는 판정하지 않습니다. 점선 사이 공백이나 끝을 벗어난 위치를 연장선으로 판정하지 않으며, 위쪽으로 복귀하면 이탈이 해제됩니다. 침범의 유지 시간과 별도로 현재 위치에서 판단합니다.

가림 밖에서 같은 점선의 현재 관측이 충분하면 세로 위치를 보정하고, 추정에 쓰지 않은 열에서 경계 오차를 교차 검증합니다. 보강 픽셀과 바퀴 안쪽 픽셀은 이 검증에 사용하지 않습니다. 전체 정렬 오차 제한과 도색 기억 수명은 유지합니다. 검증된 동일 구간에서 이미 이탈이 확인됐다면 접지점이 경계 아래에 있는 동안 유지하며, 공백이나 경계 위쪽에서는 해제합니다.

과거 이탈 사건은 기록으로 남기지만 현재 bbox 색상에는 반영하지 않습니다. 현재 접지점이 공백으로 이동하면 과거 사건이 있어도 정상색으로 돌아옵니다. 새 주행은 `r`과 Enter로 초기화합니다. 직접 보이는 도색이나 유효하게 정렬된 도색 기억이 없으면 이탈을 판단할 근거가 부족합니다. 도색 기억에는 수명과 정렬 오차 제한이 있습니다.

| 바퀴 bbox 색상 | 상태 |
| --- | --- |
| 초록색 | 정상, 유효한 접지점 사용 |
| 노란색 | 정상, bbox 하단 중앙으로 접지점 대체 |
| 주황색 | 침범 감지, 확정 시간 미충족 |
| 빨간색 | 현재 침범 확정 또는 현재 이탈 |

화면의 `W` 번호는 바퀴 추적 ID입니다. 운영 화면의 점선은 관측·보강 여부와 관계없이 노란색으로 통일합니다. 진단할 때만 실행 스크립트의 `SHOW_RESTORED_PAINT = True`로 설정하면 보강한 도색을 파란 계열로 구분할 수 있습니다. 침범·이탈 사건은 실행 로그에 남습니다.

## 주요 파일

| 경로 | 역할 |
| --- | --- |
| `main_capture_dual_youtube.py` | 캡처보드 입력, 원본·처리본 이중 송출 |

| `detector.py` | 바퀴 bbox와 접지점 검출 |

| `violation_tracker.py` | 침범 유지 시간과 확정 상태 관리 |
| `dash_referee.py` | 도로 움직임 보정, 도색 기억, 바퀴 추적, 침범·이탈 상태 관리 |

## 실행 환경

Linux, Python 3.10 이상, CUDA 지원 PyTorch·torchvision, TensorRT, FFmpeg(`ffmpeg`, `ffprobe`)를 사용합니다. GPU에 맞는 PyTorch와 TensorRT를 설치한 뒤 Python 의존성을 설치합니다.

```bash
python3 -m pip install -r requirements.txt
```

기본 모델은 별도로 준비해 프로젝트 루트의 `model/`에 배치합니다.

- `model/best_seg_rev03_FP16.engine`: 차선 세그멘테이션
- `model/best_referee_FP16.engine`: 바퀴 bbox·접지점 검출

TensorRT 엔진은 실행 장비의 GPU·CUDA·TensorRT 환경과 호환되어야 합니다.

## 설정 및 실행

프로젝트 루트에서 설정 예시를 복사하고 입력·송출 주소를 작성합니다. 기존 설정 파일이 있으면 그대로 사용합니다.

```bash
cp -n local_settings.example.json local_settings.json
```

| 설정 | 용도 |
| --- | --- |
| `DRONE_INPUT_STREAM_URL` | 유튜브 입력 주소 |
| `DRONE_OUTPUT_STREAM_RTMP_URL` | `main.py` 처리본 송출 주소 |
| `DRONE_RAW_STREAM_RTMP_URL` | 캡처보드 원본 송출 주소 |
| `DRONE_PROCESSED_STREAM_RTMP_URL` | 캡처보드 처리본 송출 주소 |

`local_settings.json`은 Git에서 제외합니다. 송출 주소에는 서버 주소와 스트림 키를 포함한 전체 RTMP URL을 입력합니다. 같은 이름의 환경변수가 있으면 JSON보다 우선합니다.

캡처보드 입력은 스크립트 상단에서 장치 번호와 송출 설정을 확인한 뒤 실행합니다.

```bash
python3 main_capture_dual_youtube.py
```

기본 요청 입력은 1920×1080, 30fps, MJPG입니다. 처리 영상은 긴 변 1280으로 줄이고 두 프레임마다 처리하므로, 해당 입력에서 처리본은 1280×720, 15fps입니다.

유튜브 입력 또는 로컬 파일은 `main.py`의 `MODE`를 `rtmp`, `video`, `image` 중 선택하고 입력 경로를 지정합니다.

```bash
python3 main.py
```

송출을 사용하지 않으면 해당 스크립트의 `*_STREAM_ENABLED`를 `False`로 설정합니다. 종료는 `Ctrl+C`입니다. 터미널에서 `r`을 입력하고 Enter를 누르면 영상 처리를 계속하면서 새 주행의 바퀴 추적과 침범·이탈 상태를 초기화합니다. Enter만 누르면 기존 재위치 모드를 전환합니다.

`TEMPORAL_DASH_ENABLED = False`로 설정하면 기존 프레임별 거리 판정으로 실행할 수 있습니다. 시간 보완을 사용하는 경로의 지속 시간은 추론 처리 속도 대신 원본 영상 시각으로 계산합니다.

## 진단 도구

프로젝트 루트에서 실행합니다. 캡처 확인에는 GUI가 필요하고, 벤치마크에는 `model/best_seg_rev03.pt`, `model/best_referee.pt`도 필요합니다.

```bash
python3 -m tools.test_capture
python3 -m tools.benchmark --img 이미지경로.png --runs 30
```

송출 없이 기존 판정과 가림 보완 결과를 비교하려면 다음 명령을 사용합니다. 0.2초는 아래 비교 실행의 설정이며 운영 기본값과 별개입니다.

```bash
python3 -m tools.evaluate_dash_referee --videos dataset/편집본/test_1.mp4 --frame-skip 2 --hold-seconds 0.2 --save-video
```

CSV에는 원시·확정 침범 판정, 바퀴 ID, 현재 이탈(`departure_active`), 이탈 발생(`departure_detected`), 과거 기록(`departure_recorded`)을 구분합니다. 이탈 사건에는 접지점, 같은 x열의 도색 아래 경계, 오차 여유와 실제 마스크를 남깁니다. 비교 영상의 왼쪽은 기존 판정, 오른쪽은 가림 보완과 이탈 판정 결과입니다. 기존 출력과의 차이를 실제 FN/FP 개선 수로 해석하려면 별도의 정답 라벨이 필요합니다.
